01 — ARCHITECTURE

Medallion Architecture & Use Cases

Bronze preserves raw data, Silver creates clean and conformed data, and Gold creates curated business-ready data for analytics.

BRONZE

Raw / Landing

Source-faithful ingestion. Preserve history and traceability. Examples: ERP, CRM, API, CSV, logs and IoT data.

SILVER

Cleaned / Conformed

Standardize types, clean duplicates/nulls, validate quality, join sources and create reusable analytical tables.

GOLD

Curated / Business-ready

Business rules, facts, dimensions, metrics and marts optimized for Power BI, dashboards, ML and decision-making.

Sources→Bronze→Silver→Gold→Power BI Semantic Model→Reports

Use Cases

Data Analysis Expressions

DAX Notes

DAX is the calculation language used in Power BI semantic models. The core mental model is not “write Excel formulas”; it is “evaluate an expression under a context.”

1. Measures vs calculated columns vs calculated tables

ObjectWhen calculatedResponds to slicers?Best use
MeasureAt query/evaluation timeYesKPIs, ratios, dynamic aggregations.
Calculated columnDuring model processingNo, value itself is storedRow-level attributes needed by the model.
Calculated tableDuring model processingNoDerived model tables, helper tables, scenarios.
Power Query custom columnDuring refreshNoData preparation before the model.

2. The two contexts you must understand

Row context

Think: current row. It is central to calculated columns and iterator functions such as SUMX.

Line Amount =
Sales[Quantity] * Sales[Unit Price]

Filter context

Think: which rows are currently visible to the calculation. Filters can come from slicers, visual axes, relationships, or DAX.

Total Sales =
SUM(Sales[SalesAmount])
CALCULATE is the context modifier. It evaluates an expression after modifying filter context. This is one of the most important DAX concepts for interview questions and real-world measures.
Store Sales =
CALCULATE(
    [Total Sales],
    Channel[ChannelName] = "Store"
)

3. Essential DAX function families

Aggregation

SUM, AVERAGE, MIN, MAX, COUNT, DISTINCTCOUNT

Context

CALCULATE, CALCULATETABLE, FILTER, ALL, REMOVEFILTERS, KEEPFILTERS

Iterators

SUMX, AVERAGEX, MINX, MAXX, RANKX

Relationship

RELATED, RELATEDTABLE, USERELATIONSHIP, TREATAS

Date / time

DATE, YEAR, MONTH, DATESYTD, DATEADD, SAMEPERIODLASTYEAR

Logic / text

IF, SWITCH, COALESCE, CONCATENATE, FORMAT

4. Interview-grade patterns

Total Sales = SUM(Sales[SalesAmount])

Profit = [Total Sales] - [Total Cost]

Profit Margin = DIVIDE([Profit], [Total Sales])

Sales LY =
CALCULATE(
    [Total Sales],
    SAMEPERIODLASTYEAR('Date'[Date])
)

YoY Growth % =
DIVIDE(
    [Total Sales] - [Sales LY],
    [Sales LY]
)

% of Total =
DIVIDE(
    [Total Sales],
    CALCULATE([Total Sales], REMOVEFILTERS(Product))
)

5. Context transition

When CALCULATE() is used without explicit filters inside a row context, it can convert the current row context into filter context. This is called context transition. It becomes especially important when iterators evaluate measures.

6. DAX debugging checklist

  1. Confirm the intended grain of the visual.
  2. Check whether the expression is a measure or calculated column.
  3. Inspect relationships and filter direction.
  4. Ask: “What is the current filter context?”
  5. Test the base measure before nesting it.
  6. Use DAX Query View and Performance Analyzer for deeper debugging.
Visual Analytics

Charts & Visual Analytics

Do not choose a chart because it looks attractive. Start with the analytical question, the data type, and the comparison you want the viewer to make.

1. Chart selection decision map

What is the question?

→
What is the data?
Categorical · Numerical · Time · Hierarchical · Geographic
→
What should the eye compare?
Length · Position · Slope · Area · Rank · Location

2. Comparison charts

Bar / Column

Best for: comparing categories. Bar charts are useful when category names are long; column charts work well for time-based or compact categorical comparisons.

Variants: clustered, stacked, 100% stacked. Use stacked bars when the part-to-whole composition across categories matters.

Ribbon

Best for: rank movement across periods. Useful when the story is “which category moved from rank 5 to rank 2?” rather than only the absolute values.

3. Trend charts

Line chart

Best for: time trends, continuous progression, seasonality and forecasting. Use a meaningful time axis and avoid excessive series.

Area chart

Best for: emphasizing magnitude/volume over time. Stacked area can show cumulative composition, but overlapping series can become difficult to compare precisely.

4. Part-to-whole charts

VisualUse whenAvoid when
Pie / DonutFew categories, one meaningful total.Many categories or precise ranking is important.
TreemapMany hierarchical categories; size represents contribution.Exact values need to be compared closely.
100% stacked barCompare composition percentages across groups.Absolute totals are the main story.
FunnelSequential stages such as leads → opportunities → wins.Unordered categories.

5. Relationship & distribution

Scatter

Use two numeric variables to examine correlation, clusters, outliers and non-linear patterns. Add bubble size for a third quantitative dimension.

Distribution thinking

For distribution analysis, ask about center, spread, skewness, multimodality and outliers. Power BI's native visual set is strongest when paired with tables, scatter plots, small multiples and appropriate aggregations; use custom visuals when a specialized distribution visual is necessary.

6. KPI, diagnostic and analytical visuals

Card

Single important value: revenue, profit, customers, margin.

KPI

Current value compared with a target and direction/status.

Gauge

Progress toward a single goal; use sparingly because a scale can consume space.

Waterfall

Bridge from starting value to ending value through positive and negative contributors.

Decomposition tree

Explore a metric through dimensions and drill into drivers.

Key influencers

Explore factors associated with a selected outcome.

Small multiples

Repeat a visual by category to compare patterns side-by-side.

Table / Matrix

Exact values, hierarchies, drill-down and detailed inspection.

7. Maps and geographic analysis

Map rule: geography should answer a spatial question. Do not use a map merely because a location field exists.

Power Query is the ETL/data-preparation layer. It connects to sources, applies repeatable transformations and loads the resulting data into the host product.

2. Core transformations

Column operations

Choose/remove, rename, reorder, split, merge, replace values, change data type.

Row operations

Filter, remove duplicates, remove errors, keep top/bottom rows, group by.

Combine

Merge queries = join horizontally. Append queries = stack rows vertically.

Reshape

Pivot and unpivot to move between wide and long representations.

Advanced

Custom columns, conditional columns, custom functions, parameters and M scripts.

Quality

Column profiling, distribution, validity checks, null/error handling and type validation.

3. M language

M is a functional, case-sensitive language. The Advanced Editor exposes the query script.

let
    Source = Excel.Workbook(File.Contents("Sales.xlsx"), null, true),
    Sales = Source{[Item="Sales",Kind="Table"]}[Data],
    ChangedType = Table.TransformColumnTypes(
        Sales,
        {{"Date", type date}, {"Amount", type number}}
    ),
    Filtered = Table.SelectRows(
        ChangedType,
        each [Amount] > 0
    )
in
    Filtered

4. Query folding

Query folding means Power Query pushes supported transformations back to the source system so the source performs as much work as possible. This can reduce data movement and improve refresh performance.

M transformations
→
Folding analysis
→
Native source query
→
Smaller result
→
Power Query engine
OutcomeSourcePower Query engine
Full foldingProcesses all possible transformations.Minimal remaining work.
Partial foldingProcesses supported transformations.Processes remaining transformations.
No foldingReturns source data.Processes required transformations.
Practical rule: for large relational sources, filter rows and select required columns early when those steps can fold. Be cautious about introducing non-foldable transformations too early.

5. Merge vs Append

Merge

Combines columns from two tables based on matching keys. Conceptually similar to SQL JOIN.

Customers + Orders
        ↓ customer_id
Customer attributes + order facts

Append

Combines rows from two or more tables with compatible schemas. Conceptually similar to UNION/UNION ALL patterns.

Sales_Jan
Sales_Feb
Sales_Mar
   ↓
Sales_All

Forecasting

Time-Series Forecasting

ARIMA, SARIMA and SARIMAX are statistical time-series models. Power BI also provides a built-in Forecast feature in the Analytics pane for line charts. These are related concepts, but they should not be treated as the same implementation.

Important Power BI distinction: Microsoft's built-in Power BI Analytics-pane Forecast is a product feature for line charts. ARIMA/SARIMA/SARIMAX are statistical model families that you typically run outside the native Power BI forecasting interface—for example in Python/R or another forecasting service—and then bring predictions back into the BI model.

1. Time-series anatomy

Level

The baseline magnitude around which the series moves.

Trend

Long-run upward or downward movement.

Seasonality

Systematic pattern repeating at a fixed frequency: monthly, weekly, quarterly, etc.

Noise

Random variation not explained by the systematic components.

Autocorrelation

Dependence between observations and their previous lags.

Exogenous drivers

External variables that may explain the target, such as price, promotions or weather.

2. Stationarity

A stationary series has stable statistical properties over time, broadly meaning that its mean, variance and autocovariance structure do not systematically drift with time.

ARIMA-family models often use differencing to transform a non-stationary series into a stationary one.

First difference: Δyₜ = yₜ − yₜ₋₁
Seasonal difference: Δₛyₜ = yₜ − yₜ₋ₛ

3. ARIMA

ARIMA(p,d,q) combines autoregression, differencing and moving average behavior.

ParameterMeaningIntuition
pAR orderHow many lagged observations influence the current value.
dDegree of differencingHow many times the series is differenced to remove non-stationarity.
qMA orderHow many lagged forecast errors influence the current value.
AR component: yₜ depends on yₜ₋₁, yₜ₋₂, …
MA component: yₜ depends on past errors εₜ₋₁, εₜ₋₂, …

4. SARIMA

SARIMA(p,d,q)(P,D,Q,s) extends ARIMA with a seasonal component.

Non-seasonalSeasonal
p = AR orderP = seasonal AR order
d = differencingD = seasonal differencing
q = MA orderQ = seasonal MA order
s = seasonal period

Examples of s: 12 for monthly data with annual seasonality; 7 for daily data with weekly seasonality; 4 for quarterly data with annual seasonality.

5. SARIMAX

Typical X variables: marketing spend, price, promotions, holidays, weather, macroeconomic indicators or capacity constraints. The external variables must be available for the forecast horizon—or themselves forecast—if they are required as future inputs.

6. Model identification: ACF and PACF

ACF

Autocorrelation function. Helps inspect correlation between a series and its lagged versions. It is commonly used to reason about MA terms and remaining serial dependence.

PACF

Partial autocorrelation function. Measures correlation at a lag after controlling for shorter lags. It is commonly used to reason about AR terms.

ACF/PACF are diagnostic tools, not magic parameter selectors. Candidate orders should be validated using residual diagnostics and out-of-sample performance.

8. Train/test split for time series

Do not randomly shuffle a time series before splitting. The future must not leak into the training set.

TRAIN — historical observations
TEST — future holdout

9. Forecast evaluation

MetricMeaningCaution
MAEAverage absolute forecast error.Easy to interpret in target units.
RMSESquare-root mean squared error.Penalizes large errors more heavily.
MAPEMean absolute percentage error.Problematic around zero/very small actuals.
sMAPESymmetric percentage-style error.Still needs careful interpretation.
MASEError scaled relative to a naive benchmark.Useful for comparing series with different scales.

10. Python example: SARIMAX

from statsmodels.tsa.statespace.sarimax import SARIMAX

model = SARIMAX(
    y_train,
    exog=X_train,
    order=(1, 1, 1),
    seasonal_order=(1, 1, 1, 12),
    enforce_stationarity=False,
    enforce_invertibility=False
)

fit = model.fit(disp=False)

forecast = fit.get_forecast(
    steps=len(y_test),
    exog=X_test
)

pred = forecast.predicted_mean
interval = forecast.conf_int()

Semantic model

Data Model & Performance

A good Power BI report is not just a collection of charts. The semantic model controls correctness, reusability, performance and the behavior of DAX.

1. Star schema

2. Relationship checklist

  • Prefer clear dimension-to-fact relationships.
  • Validate cardinality: one-to-many is common in star schemas.
  • Avoid unnecessary many-to-many relationships.
  • Use a dedicated date dimension for robust time intelligence.
  • Use inactive relationships deliberately and activate them with USERELATIONSHIP when needed.

3. Performance mindset

Reduce data

Remove unused columns and rows before loading where possible.

Optimize model

Use appropriate data types and a sensible star schema.

Optimize DAX

Build reusable base measures and avoid unnecessarily expensive iterator/filter patterns.

Fold queries

Push transformations to capable sources when possible.

Analyze visuals

Use Performance Analyzer to identify slow visual queries.

Control cardinality

High-cardinality text columns can increase model size and memory pressure.
